# History 说明

## 用途

- 保存阶段性上下文整理、经验沉淀和问题回顾。
- 新整理的历史文档先放本目录根下，文件名使用日期前缀。
- 历史文档优先写“背景、关键经过、当前结论、可复用经验”。

## 分层原则

- `history/` 负责留痕和回溯，不替代长期入口文档。
- 能长期复用的经验，要继续回填到对应 `README.agent.md` 或专题文档。
- 已整理完成、不再活跃的历史 md 归入 `archive/`。

## 已沉淀经验

- 规则来源判断以 `zprules` 实际输出为准，并明确区分用户级 / workspace 级 / repo 级入口。
- 大型 repo 的根入口默认收敛成“导航 + 分流 + 硬约束”。
- 历史描述如果可能被误读成当前状态，要显式标成“迁移前/历史口径”。
- 清理 `outputs/` 或其他运行入口目录时，先保原路径可用。
