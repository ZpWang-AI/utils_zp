# Routine Events

本文件用途：记录本仓库里会经常重复发生、但又不适合写进 `PROGRESS.agent.md` 或 `ISSUE.agent.md` 的常规事件，便于持续追踪和统一处理口径。

## 适用范围

- 适合记录会反复出现的协作事件，例如：`code review`、CLI 文档同步、规则文档更新、配置巡检、`tmp/` 无用文件清理
- 不适合记录一次性的功能开发过程；这类事项继续写 `.agent/PROGRESS.agent.md`
- 不适合记录明确缺陷、阻塞或待修复问题；这类事项继续写 `.agent/ISSUE.agent.md`
- 如果某类重复事件已经沉淀成稳定 SOP，可在这里保留索引和最新约定，不必每次重复写长说明

## 记录建议

- 所有事项统一记录在 `当前事件` 下，使用 `1. 2. 3.` 编号列表，不使用 `-` 列表
- 条目标题推荐格式：`1. 事件名称（状态）`
- 每条事件建议固定补充：`标签：`、`触发场景：`、`记录方式：`、`涉及文件：`、`最近一次时间：`
- `标签：` 统一写成 `优先级=P0/P1/P2/P3；问题类型=...`；`问题类型` 可优先使用 `代码评审`、`文档同步`、`流程规范`、`质量巡检`
- `最近一次时间：` 使用 `YYYY-MM-DD HH:MM:SS`；如果只是补录历史规则，可注明为补记时间
- 当某个事件只是一段时间内临时存在，后续不再需要追踪时，可以删除或归档到未来单独的 routine archive

## 当前约定

- `PROGRESS` 记录一次性开发事项，`ISSUE` 记录问题和待修复项，`ROUTINE` 记录可重复发生的常规事件
- 同一件事如果既有“本次开发进展”，又属于“长期重复事件”，优先在对应开发或 issue 文档里记本次动作，再在这里沉淀通用模式
- 这里优先写“怎样追踪这类事件”，不是逐字复制每次执行细节
- routine 执行中如果沉淀出明确缺陷、阻塞或待修动作，不要只留在本文件，应继续转记到 `.agent/ISSUE.agent.md`
